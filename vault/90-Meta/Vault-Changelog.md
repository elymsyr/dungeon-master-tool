# Vault Changelog

> [!note] Append-only log of vault structural changes. Newest first.

- **2026-07-30** — **Official-pack audit rewritten around linking; duplication measured.** `flutter_app/docs/open5e_content_audit.md` was a field-coverage audit; it is now a from-scratch content audit whose first rule is **never create what you can link** ([[Package-Links]], shipped the day before, is the mechanism). New §2 states the contract at both levels: (a) *entity* level — the built-in SRD pack is in scope everywhere implicitly (overlay + [[srd_core_bootstrap]] + `mergeBuiltinWithPackages`), so a pack re-shipping "Acolyte"/"Fireball"/"Amphibious" only shadows it and should not be emitted; pack→pack sharing needs a `metadata.links` entry carrying **both** the catalog `slug` (what [[build_catalog]] turns into `requires`) and the local `name` (= the target's `metadata.title`, since [[package_payload_importer]] names the row after the title — `PackageLink.fromJson` ignores `slug`, `_requiredSlugs` needs it, so one key alone silently fails on one side); (b) **ref-inside-a-card** level — a feat naming a built-in class as a prerequisite must `softRef('class', …)`, never mint a local Paladin, with a 5-step resolution order (Tier-0 `lookup` → built-in softRef → linked-pack softRef → in-pack hard `ref` → `mechanical_notes`). Also new: cause code `D`, marker 🔗, a scope rule that green rows are claims to re-verify (⚠ constants), §2.4 listing four ⛔ policy rows that links have **invalidated** (`spell.class_refs`, `magic-item.base_item_ref`, gear stubs, `monster.gear_refs`), and §2.5 warning that a name collision is not proof of identical content (A5E restats SRD deliberately). Roadmap gains Stage L (dedup/link) and Stage V (re-verify + rebuild the drifted catalog). New tool + note [[dupe_census]] (19 packs / 20,712 entities → **4,331 redundant, 20.9%**; softRef surface = 135, of which 0 point at another bundled pack), plus the previously-missing note for its sibling [[audit_packs]]; both wired into [[Content-Pipeline]].
- **2026-07-29** — **Package→package links.** The built-in pack and the official Open5e packs ship the same races/classes/items/spells twice, and the only sharing mechanism was hard-coded: `srdReferenceEntitiesProvider` overlaid SRD into every other package, `SrdCoreBootstrap` linked SRD into every world — the idea worked but could not be pointed at anything else. A package can now **link** other packages: the stores stay separate, but the linked package's entities appear in the linking package's editing view and follow it into every world import and catalog download. New system note [[Package-Links]] plus tracking notes [[package_link_service]] and [[world_package_installer]]. **Storage is `packages.state_json['links']`, not a table** — `_saveToDb` routes non-typed top-level keys into `state_json`, so export/marketplace/personal-cloud-sync/trash-restore carry links for free, and a Drift table would bump `schemaVersion` past the v12 fresh cut (renaming every user's DB). Resolution is a soft ref (`package_id` then `name`), so a link survives a marketplace download or a Copy, and a dangling link is a warning at read, install and download alike — never a failure. **The sharp edge**: authoring against the overlay lets a card hold a *foreign* pack-entity id, and [[package_sync_service]] built `packToWorld` from only the package being synced — so such a ref dangled in the world. New `sync(foreignRefs:)` + `WorldPackageInstaller.buildForeignRefIndex` (real `world_entities` rows ∪ [[builtin_synth]] synth ids) fixes it, and closes the same pre-existing hole for refs picked from the SRD overlay. New [[world_package_installer]] also collapses four copies of the *register → Tier-0 index → sync* block ([[import_package_dialog]], [[world_packages_provider]], [[world_packages_section]], [[world_mirror_applier]]). `EntityNotifier`'s `overlaySrdReference: bool` → `referenceOverlayFor: String?`. Uninstall deliberately does **not** cascade (no provenance column, see above) and deleting a linked-to package is allowed with a warning. 26 new tests across `package_link_service_test` + `world_package_installer_test`; new `test/support/test_database.dart` resolves `libsqlite3.so.0` so Drift-backed tests run without `libsqlite3-dev`. Mechanism only — deduplicating the official packs (`docs/open5e_content_audit.md`) is the follow-up this unblocks.
- **2026-07-29** — **SRD bootstrap crashed on startup: int-keyed `count_by_level` maps.** Six `resource_pool_grants[].count_by_level` tables in `feats_class.dart` were authored with **int** keys (`{1: 2, 3: 3, …}`); `jsonEncode` refuses a Map with non-String keys, so [[srd_core_package_bootstrap]] threw `Converting object to an encodable object failed: _Map len:6` and the Packages tab showed a startup error with no SRD pack installed. Keys are now strings, matching the canonical wire shape everywhere else ([[resource_pool_resolver]] already tolerated both). New `test/domain/srd_core_json_encodable_test.dart` runs every jsonEncode the bootstrap performs over the real pack + schema + seed rows, so a non-encodable value can never reach startup again. `srdCorePackVersion` → `1.0.5` so existing installs re-seed.
- **2026-07-29** — **Auto-grant edge inverted: the granting card owns the level.** A feat used to declare its own source (`auto_granted_by: [{class, at_level}]`) while the Class card carried an unlinked narrative `features` row for the same feature — one fact stated twice, and in the shipped SRD the two **disagreed on nine features** (Warlock Mystic Arcanum ×4 sat at L5/7/9/11 instead of L11/13/15/17; Champion, Hunter and Evoker rows were swapped or off) plus **six features had no class row at all**. `auto_granted_by` and `FieldType.autoGrantSources` are deleted from schema, editor and content; a Class/Subclass `features` row's `granted_feat_refs`/`granted_trait_refs` is now the single declaration, with new flat `granted_feat_refs` on Species/Subspecies. New `wireFeatureGrants` (Pass 0 of [[srd_core_pack]]) writes the edge at pack-build time and reports every row it had to move or synthesize. Two long-standing **silent id collisions** surfaced and were fixed — `Uncanny Dodge` (Rogue L5 vs a Hunter option) and `Fiendish Vigor` (Fiend Patron L3 vs a Warlock invocation) shared `slug:name` ids, so one overwrote the other; the builder now throws on duplicates, which also caught `trait:Evasion` and `trait:Brave` (monster vs PC wordings). [[character_resolver]] Pass 4b now walks the four cards the character actually has instead of scanning the whole world, and three byte-identical private `_isAutoGranted` copies collapsed into new [[auto_granted_feats]]. New [[auto_grant_inversion]] converts existing worlds and old packs (cross-entity, so it runs over whole maps unlike [[rule_effects_migration]]). Also fixed: the `features` row editor never drew the row's `name`, so the class card showed a summary line with no feature title. New `feature_grant_edge_test` (15 tests) pins the whole thing; `srdCorePackVersion` → `1.0.4`.
- **2026-07-29** — "One mechanic, one field" audited, enforced and fixed. **Four defects** the grant block had been hiding: (1) `class.granted_languages` was authored on Druid/Rogue and read by the wizard but *never* by [[character_resolver]] — Druidic and Thieves' Cant never reached a sheet; (2) `granted_spells_at_level` was read by the resolver and used by six subspecies with **no `FieldType` and no schema field** — invisible and uneditable (new `spellsAtLevel` type + `SpellsAtLevelFieldWidget`, now key 41 of the contract); (3) seven attributes were authored with no declared field at all (`class.granted_tool_refs`/`l1_order_feat_category`/`weapon_mastery_filter`, `background.granted_tool_variant_group`, `subspecies.legacy_subspecies_key`, plus the three subclass proficiency extensions the resolver reads) — this was the red `srd_core_pack_test` integrity check, now green; (4) [[resource_pool_resolver]] only accepted an *unresolved* `pool_ref`, so the level-up dialog showed **zero pools for every class** while the sheet showed them correctly. **Four new test files**: `grant_contract_test` (schema ↔ resolver ↔ content agree; no synonym pair on one card; every field type has a real editor), `grant_field_isolation_test` (all 41 keys, each authored alone and diffed slice-by-slice — plus proof that legacy `rule_effects`/`granted_modifiers`/`effects` rows are inert), `grant_source_matrix_test` (one bundle × every card type), `grant_reader_agreement_test` (12 SRD classes × 12 levels: chargen preview == resolved sheet), and new suites for `weapon_mastery_resolver` + `pending_choices`. Notes updated: [[Grant-Resolution]] (41 keys, why Class/Subclass/Background stay outside the block), [[character_resolver]], [[field_schema]], [[resource_pool_resolver]].
